
## Раздел 1. Постановка

| поле                        | решение                                                                                                                                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Бизнес-действие             | Изменить порядок ручного разбора: из примерно 35 тыс. помеченных операций в месяц первыми отдавать наиболее рискованные в пределах мощности около 10 тыс. Модель не выносит вердикт и не блокирует платёж                    |
| Объект и единица решения    | Одна операция с point-in-time контекстом клиента, контрагентов и предшествующей истории                                                                                                                                      |
| Момент                      | Near-real-time или микропакет до постановки в очередь. Пилот работает в тени и не влияет на проведение операции                                                                                                              |
| Операция                    | Ранжирование по риску; дополнительный канал - поиск аномалий                                                                                                                                                                 |
| Модальность                 | Таблицы, временные последовательности, категориальные справочники, текст назначения; граф связей - только при подтверждённой допустимости и качестве идентификаторов                                                         |
| Выход модели                | Риск-скор/аномальность, ранг, причины/факторы, версия модели, флаг недостатка данных. Это не метка `схема`                                                                                                                   |
| Бизнес-выход                | Аудируемая приоритетная очередь с обязательными сигналами и объяснением; решение и основание фиксирует сотрудник финмониторинга                                                                                              |
| Источник правильного ответа | Экспертная оценка по гайдлайну и исход расследования как разные уровни сигнала; поздние формальные подтверждения используются отдельно. Постоянная вероятностная контрольная выборка позволяет оценивать непроверенную часть |
| Конвейер                    | Контроль качества -> обязательные правила -> point-in-time признаки -> скоринг/аномальность -> политика очереди и квоты выборки -> ручная проверка -> расследование -> отложенные исходы -> мониторинг и переобучение        |
| Альтернативные постановки   | Пилот: ранжирование 35 тыс. уже помеченных операций. Цель после проверки: дополнительный поиск по всему потоку 20–25 млн. Переход открывается отдельным решением, поскольку распределение и цена пропуска отличаются         |

## Раздел 2. Оценка качества

### Что именно измеряется ?

| поле                | решение                                                                                                                                                                                                                                                                                                                             |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Бизнес-метрика      | Число и доля операций, которые по единому экспертному гайдлайну требуют углублённого расследования, найденных в первых 10 тыс. проверок; время до разбора; стоимость проверки; guardrails по приостановкам и жалобам. Формально подтверждённые случаи отслеживаются как поздний outcome, но их недостаточно для оперативной метрики |
| Положительный класс | Для оперативной оценки - `по доступным на момент проверки сведениям операция требует углублённого расследования по зафиксированным критериям`. Это не тождественно `подтверждённая схема`. Метрики по формально подтверждённым случаям считаются отдельно                                                                           |
| Метрика под решение | `precision@K` и yield при `K =` фактическая месячная мощность; uplift к текущей очереди при одинаковом K. Для всего потока - оценка recall/yield с inverse-probability weighting по вероятностной выборке. Калибровка нужна для стабильной политики порогов, но не заменяет ranking-метрики                                         |
| Baseline            | Текущие правила/внешние сигналы и приоритизация преимущественно по сумме. Дополнительные технические baseline: случайный порядок внутри страт и простой взвешенный rule score                                                                                                                                                       |
| Проверочная выборка | Проспективная, не использованная в обучении: случайная или стратифицированная вероятностная выборка из всего потока плюс независимые срезы верхушки модели и baseline. Вероятность включения сохраняется для взвешенной оценки. Разбиение по времени исключает утечку будущего                                                      |
| Рабочая точка       | Не фиксированный score, а верхние K с учётом мощности, обязательных правил и квоты исследования. Для пилота K не увеличивает текущие 10 тыс. ручных разборов; часть мощности резервируется под контрольную выборку                                                                                                                  |
| Цена ошибок         | Пропуск: схемный риск, потери и регуляторные последствия. Ложный высокий приоритет: 12 минут специалиста и задержка других кейсов; последующая необоснованная приостановка может привести к жалобе и оттоку                                                                                                                         |
| Guardrails          | Не растут объём ручной очереди, доля необоснованных приостановок, жалобы и время обработки; обязательные правила не обходятся; нет автономного отказа/блокировки; качество контролируется по сегментам, суммам и новым клиентам                                                                                                     |

### Приёмочный набор

1. Провести калибровочную фазу на 300–500 двойных экспертных оценках, чтобы
   определить распространённость классов, согласованность и требуемый размер
   основного набора
2. Основной набор формировать вероятностно из всего потока со стратами по
   сумме, сегменту, каналу, ОКВЭД, новым/старым клиентам и наличию текущего
   правила. Отдельно включить верхушки ranking-кандидатов и baseline
3. Размер задаётся power analysis для минимального экономически значимого
   uplift, утверждённого владельцем процесса. Начальный бюджет для оценки
   стоимости - 2 000 контрольных операций и по 1 000 операций из верхушки
   baseline и нового ranking. При 12 минутах это около 800 экспертных часов;
   пересечения дедуплицируются. Это бюджет, а не обещание статистической
   мощности при редком классе
4. Не менее 10% основного набора и все спорные случаи размечают два эксперта.
   Сохраняются причины, уверенность и расхождения, а не только бинарная метка

### Пороги решения

- Гайдлайн пригоден, если после разбора расхождений коэффициент
  Krippendorff's alpha не ниже 0,67 - минимального уровня для осторожных
  выводов; ниже этого сначала уточняется постановка, а не обучается
  классификатор
- Ranking проходит пилот, если нижняя граница 95% доверительного интервала
  uplift `precision@K` относительно процесса baseline выше нуля, а оценённая
  выгода превышает стоимость разметки, эксплуатации и дополнительных
  расследований. Требуемый бизнесом минимальный uplift фиксируется до
  раскрытия результата пилота
- В каждом критичном сегменте модель не должна быть хуже baseline более чем на
  заранее согласованную non-inferiority margin. Число margin определяет
  владелец риска после калибровочной фазы; без него автоматическое продвижение
  запрещено
- Лимит очереди и SLA - жёсткие ограничения. Рост приостановок или жалоб
  останавливает rollout, даже если offline ranking улучшился

Провал только на новых клиентах означает отсутствие достаточной истории и
требует отдельной cold-start политики. Провал на дроблении означает нехватку
временных/связных признаков. Провал в непроверенной части при успехе на старой
очереди означает воспроизведение логики текущих правил и запрещает расширение
на весь поток

## Раздел 3. Готовность данных

| поле                          | решение                                                                                                                                                                                                                                                                            |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Решение                       | Приоритет ручной проверки, а не автоматический вердикт о схеме                                                                                                                                                                                                                     |
| Объект и гранулярность        | Операция; дополнительно оконные агрегаты клиента/контрагента. Все признаки восстанавливаются на фактический момент решения                                                                                                                                                         |
| Источник и владелец           | Core banking/платежи - владелец платежный блок; правила и кейсы - финмониторинг; клиент/ОКВЭД/KYC - клиентский и комплаенс-контуры; внешние сигналы - владелец договора; витрина и lineage - data platform. Именованные владельцы назначаются до доступа                           |
| Источник правильного ответа   | (1) новая экспертная разметка по гайдлайну; (2) исход расследования; (3) позднее формальное подтверждение. Срабатывание правила, внешний сигнал и `эскалировано` - только слабые метки/признаки, не эталон                                                                         |
| Доступность признаков в проде | Проверяется point-in-time аудитом. Будущие исходы, последующие блокировки, признаки, рассчитанные после операции, и изменённые задним числом справочники запрещены                                                                                                                 |
| Разметка                      | Финмониторинг размечает причины и требуемое действие по версии гайдлайна. Двойная разметка и adjudication измеряют согласованность. Разметка поступает одновременно из приоритетной очереди и постоянной вероятностной контрольной выборки                                         |
| Смещение отбора               | Исторически проверялись срабатывания правил/внешних сигналов и крупные суммы; поэтому проверенное не представляет весь поток, а непроверенное не является отрицательным. Обучение только на новой очереди создало бы feedback loop модели                                          |
| Репрезентативность            | Контрольная выборка покрывает сегменты, суммы, каналы, ОКВЭД, возраст клиента, регионы и наличие/отсутствие правила. Редкие дорогие сценарии oversample с сохранением вероятности отбора                                                                                           |
| Объём                         | 20–25 млн операций в месяц; около 35 тыс. помечаются, 10 тыс. разбираются, около 400 эскалируются. Формально подтверждённых случаев - единицы и с задержкой: их недостаточно для supervised fraud classifier. Стартовый разметочный бюджет описан выше и уточняется power analysis |
| Качество                      | Проверить дубли/отмены, идентификаторы сторон, пропуски ОКВЭД и назначения, изменение справочников, часовые пояса, связность клиента и консистентность исходов кейса. Нужны data contracts и point-in-time snapshots                                                               |
| Право использовать            | Банковская тайна и персональные данные. Комплаенс, DPO, юристы и ИБ подтверждают цель, основание, минимизацию, регион, сроки, доступ, договор обработчика и допустимость внешних сигналов/графа. Архитектурное решение не является таким заключением                               |
| Вердикт                       | **Разрыв с планом закрытия.** Не хватает именно несмещённого и согласованного экспертного сигнала, а не общего объёма транзакций. Закрытие: гайдлайн -> калибровка разметчиков -> постоянная вероятностная выборка + очередь -> point-in-time витрина -> теневой эксперимент       |

### Размещение и предварительный шортлист

**Жёсткие ограничения:** данные не покидают одобренный контур до заключений
контрольных функций; обязательные правила сохраняются; полный аудит входов,
версии, факторов и действий; prod не зависит от публичного API; модель выдаёт
ранг и причины, а не автономное решение

**Пилот:** on-prem в изолированном аналитическом контуре на минимизированных
point-in-time данных. **Целевой прод:** on-prem либо self-hosting в одобренном
private cloud. Гибрид допустим только по нечувствительным операциям
разработки/мониторинга; сырые операции и назначения наружу не передаются

После отсечения остаются:
1. rule score как обязательный baseline
2. Isolation Forest/robust statistical anomaly score как безучительный
   кандидат для новых паттернов
3. интерпретируемый GBDT/ranking (CatBoost/LightGBM-класс) на слабых сигналах
   и накопленной экспертной разметке, с sample weighting
4. объединение rule, anomaly и supervised score прозрачной политикой

Публичный API исключён для пилота из-за передачи чувствительных данных,
зависимости и невозможности доказать воспроизводимость. Глубокий end-to-end
классификатор исключён на старте из-за дефицита эталона и слабой
объяснимости. Итоговый кандидат выбирается только проспективным shadow
сравнением по процедуре выше. Если ни один кандидат не даёт доказуемого
uplift, остаётся текущий baseline и продолжается сбор меток

## Раздел 4. Карточка эксперимента

| поле                            | решение                                                                                                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Где именно теряем ?             | Внутри 35 тыс. помеченных операций 10 тыс. выбираются с сильным уклоном к сумме; неизвестно, сколько полезных кейсов остаётся в 25 тыс. хвоста и во всём непроверенном потоке                                            |
| Гипотеза причины                | Временные, текстовые и контрагентские паттерны дают дополнительный сигнал риска сверх текущих порогов и суммы                                                                                                            |
| Конкурирующие объяснения        | Текущие правила уже извлекают почти весь доступный сигнал; эксперты не могут согласованно определить целевое действие; полезный сигнал появляется только спустя месяцы; модель просто копирует selection bias            |
| Рычаг                           | Новая разметка, point-in-time признаки, ranking loss, политика top-K и постоянная exploration-квота                                                                                                                      |
| Дешёвый различающий эксперимент | Четырёхнедельный shadow ranking без влияния на платежи; слепое сравнение model top-K, baseline top-K и вероятностной контрольной выборки по единому гайдлайну                                                            |
| Ожидаемый эффект                | Не задаётся неподтверждённым процентом. До просмотра результатов бизнес фиксирует минимальный uplift, окупающий разметку и эксплуатацию; статистический gate - нижняя граница 95% CI выше нуля                           |
| Стоимость проверки              | Стартовая оценка - до 4 000 уникальных разборов, около 800 экспертных часов плюс adjudication, витрина и shadow-интеграция. После калибровки объём пересчитывается по мощности теста                                     |
| Критерий остановки              | Низкая согласованность после доработки гайдлайна; отсутствие положительного uplift; ухудшение критичного сегмента/guardrail; невозможность получить правовое или ИБ-согласование; признаки доступны только после решения |
