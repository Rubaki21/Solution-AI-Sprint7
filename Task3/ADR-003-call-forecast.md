
Статус: **предварительное**

Дата: 2026-10-10

Инициатива: прогнозировать нагрузку на колл-центр для планирования смен

## Контекст

Модель должна прогнозировать calls/workload и неопределённость. Расчёт
численности, трудовые ограничения и расписание являются детерминированной
оптимизацией; итог утверждает WFM-планировщик

## Жёсткие ограничения

- В модель не поступают аудио, текст и идентификаторы клиента
- Будущие события используются только если были известны на момент прогноза
- Жёсткие трудовые ограничения нельзя ослабить ML-рекомендацией
- Есть seasonal fallback, ручной override и версионированный approval

## Рассмотренные варианты

| вариант                    | за                                      | против                                                      | решение                                 |
| -------------------------- | --------------------------------------- | ----------------------------------------------------------- | --------------------------------------- |
| Seasonal naive             | Надёжен и прозрачен                     | Не учитывает события                                        | Обязательный fallback/baseline          |
| ETS/SARIMAX                | Интерпретируемая сезонность             | Сложнее масштабировать на много рядов                       | Кандидат                                |
| Global GBDT quantile model | Общие закономерности, known-future, CPU | Нужны feature pipeline и калибровка                         | Основной ML-кандидат                    |
| Deep temporal model        | Может помочь при множестве рядов        | GPU/TCO и сложность                                         | Только challenger при доказанном uplift |
| Публичный API              | Минимум эксплуатации                    | Не нужен для компактной задачи, зависимость/передача данных | Отклонён                                |

## Решение

После data audit провести on-prem rolling backtest seasonal naive,
ETS/SARIMAX и global GBDT по единому контракту квантилей. Пилот работает в
shadow. Прод - self-hosting on-prem или в одобренном private cloud

Forecast Service возвращает распределение workload; отдельный оптимизатор
применяет SLA, стоимость, навыки и трудовые ограничения. Победитель выбирается
по MASE/WAPE, calibration и симулированной стоимости staffing. Сложная модель
не принимается без доказуемого выигрыша над простым baseline

## Допущения

- Есть непрерывная история минимум для шести проверяемых сезонных циклов
- Topology очередей и offered calls можно восстановить
- WFM формализует цену недо-/перепланирования и целевой SLA

## Риски и меры

Смена topology версионируется; незапланированные инциденты идут через override;
coverage квантилей мониторится; оптимизатор и прогноз диагностируются
раздельно; утверждённый план не перезаписывается автоматически

## План выхода

Контракт квантилей и feature definitions независимы от библиотеки; seasonal
baseline обслуживает все очереди; артефакты хранятся во внутреннем registry;
предыдущий прогноз и расписание доступны для rollback

## Триггеры пересмотра

- история не проходит полноту/topology audit
- ML не превосходит baseline либо staffing simulation не даёт эффекта
- хороший прогноз не улучшает SLA - пересмотреть AHT/shrinkage/optimizer
- меняется горизонт, гранулярность или автоматизация публикации смен
- private cloud не проходит правовой/ИБ gate или on-prem не выдерживает SLO
