
## Инициатива №1. Приоритизация подозрительных операций

### Полная постановка

| поле                                 | решение                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Инициатива без слова `AI`            | Для каждой операции рассчитать оценку риска транзита, обналичивания или дробления, объяснить основные факторы и поставить наиболее рискованные операции в очередь финансового мониторинга; сотрудник принимает решение по установленной процедуре                                                                                                                                  |
| Какое действие изменится ?           | Вместо приоритета почти только по сумме сотрудники получают ранжированную очередь в пределах доступной мощности - около 10 тыс. разборов в месяц - и видят связанные операции клиента. Модель не блокирует платёж и не выносит окончательную оценку                                                                                                                                |
| Где нужна обучаемая закономерность ? | В оценке риска операции и связанных паттернов клиента/контрагентов, которые нельзя устойчиво перечислить пороговыми правилами. Обязательные контрольные правила, проверки ограничений, аудит, распределение кейсов и решение сотрудника детерминированы                                                                                                                            |
| Чего не хватает ?, допущения         | Нет готовой разметки `схема / не схема`; эскалация отражает прежний отбор, а непроверенные операции нельзя считать отрицательными. Предполагается доступ к историческим срезам признаков без утечки будущего, исходам расследований и связанным операциям. Для пилота модель ранжирует 35 тыс. уже помеченных операций; выход на весь поток - отдельный этап после оценки смещения |
| Вердикт                              | **Гибрид; брать с условием:** human-in-the-loop, новая программа разметки и проспективная проверка на случайной/стратифицированной контрольной выборке                                                                                                                                                                                                                             |

### Постановка модели и процесса

| поле                        | решение                                                                                                                                                                                                                                                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Бизнес-действие             | Изменить порядок разбора очереди так, чтобы при той же мощности раньше находить больше действительно требующих расследования операций, не увеличивая необоснованные приостановки                                                                                                                                                            |
| Объект и единица решения    | Одна операция; признаки строятся также на истории клиента, контрагентах и связанных операциях только на момент оценки                                                                                                                                                                                                                       |
| Момент                      | Near-real-time для постановки в очередь либо микропакетами в течение установленного процессом SLA. На пилоте - теневой расчёт без влияния на проведение и блокировку                                                                                                                                                                        |
| Операция                    | Ранжирование по риску; дополнительно - поиск аномалий для новых паттернов                                                                                                                                                                                                                                                                   |
| Модальность                 | Табличные транзакции и временные последовательности, свободный текст назначения платежа, категориальные справочники; при наличии правового основания - граф связей клиентов и контрагентов                                                                                                                                                  |
| Выход модели                | Калиброванный риск-скор, ранг, тип/причина риска, основные факторы и индикатор недостаточности данных                                                                                                                                                                                                                                       |
| Бизнес-выход                | Приоритетный кейс в рабочем месте финмониторинга с операцией, контекстом, сработавшими обязательными правилами и объяснением; сотрудник выбирает действие и фиксирует основание                                                                                                                                                             |
| Источник правильного ответа | Не отметка `эскалировано`. Используется иерархия исходов: решение углублённого расследования по единому гайдлайну, последующие подтверждения/опровержения и формально подтверждённые случаи после задержки. Для непроверенного потока - независимая стратифицированная экспертная разметка; спорные случаи adjudication двумя специалистами |
| Конвейер                    | Детерминированные проверки качества и обязательные правила -> построение point-in-time признаков -> ML-риск и/или аномальность -> правила приоритизации с учётом мощности и критичных сигналов -> рабочее место сотрудника -> решение и причины -> контур обратной связи и отложенных исходов                                                     |
| Альтернативные постановки   | (1) Ранжировать только 35 тыс. операций, уже отобранных правилами; (2) искать риск во всех 20–25 млн операций; (3) оценивать клиента, а не операцию. **Вопрос бизнесу:** цель первого релиза - повысить качество текущей очереди или расширить покрытие всего потока? В работе принято (1) для пилота, (2) как возможная целевая постановка |

## Инициатива №2. Оцифровка документов кредитной заявки

### Полная постановка

| поле                                 | решение                                                                                                                                                                                                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Инициатива без слова `AI`            | Принять PDF, скан, фото или таблицу из кредитного пакета, определить тип документа, извлечь заданные поля с координатами и уверенностью, проверить формат и передать результат сотруднику на подтверждение                                                         |
| Какое действие изменится ?           | Андеррайтер не вводит весь документ вручную: он проверяет подсвеченные поля и исправляет только ошибки или низкоуверенные значения. Подтверждённые данные поступают в кредитное досье                                                                              |
| Где нужна обучаемая закономерность ? | Выравнивание изображения, OCR рукопечатного/печатного текста, классификация типа и версии документа, понимание таблиц и извлечение полей. Проверки форматов, контрольных сумм, обязательности и арифметики реализуются правилами                                   |
| Чего не хватает ?, допущения         | Нужен каталог типов документов и полей, распределение форматов/качества, права на использование документов и история ручных исправлений. Предполагается, что пилот ограничат 2–3 частыми типами документов и что сотрудник остаётся ответственным за подтверждение |
| Вердикт                              | **Гибрид; брать с условием:** ограничить пилот типами с достаточным объёмом и ввести обязательное подтверждение критичных полей                                                                                                                                    |

### Постановка модели и процесса

| поле                        | решение                                                                                                                                                                                                                                                                                               |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Бизнес-действие             | Сократить средние 1,5 часа разбора пакета и число ошибок ручного ввода без автоматического кредитного решения                                                                                                                                                                                         |
| Объект и единица решения    | Технически - документ, страница и отдельное поле; бизнес-единица - пакет одной кредитной заявки                                                                                                                                                                                                       |
| Момент                      | По загрузке пакета, асинхронно до начала работы андеррайтера; повторная обработка по запросу при замене документа                                                                                                                                                                                     |
| Операция                    | Классификация документа и извлечение структурированных значений; для таблиц - восстановление структуры                                                                                                                                                                                                |
| Модальность                 | Документ, изображение, текст и таблица                                                                                                                                                                                                                                                                |
| Выход модели                | Тип документа; текст и координаты; пары `поле - значение - уверенность - источник`; структура таблиц; признаки нечитаемости                                                                                                                                                                           |
| Бизнес-выход                | Предзаполненная карточка заявки, визуальная привязка значения к оригиналу, очередь полей на проверку и протокол исправлений                                                                                                                                                                           |
| Источник правильного ответа | Подтверждённые сотрудником значения и исправления, сверенные с оригиналом. Для тестовой выборки - двойная независимая разметка критичных полей и разрешение расхождений; значения из последующего решения по кредиту сами по себе эталоном OCR не являются                                            |
| Конвейер                    | Антивирус и проверка формата -> нормализация/разбиение PDF -> улучшение изображения -> ML-классификация и OCR/извлечение -> детерминированная валидация -> confidence routing -> подтверждение сотрудником -> запись в кредитное досье и журнал качества                                              |
| Альтернативные постановки   | (1) Только текстовый OCR; (2) извлечение согласованного набора полей; (3) сразу расчёт финансовых показателей. **Вопрос бизнесу:** нужен поисковый текст, предзаполнение полей или готовые показатели? Для пилота выбрано (2), поскольку у него проверяемый эталон и прямой эффект на время обработки |

## Инициатива №15. Прогноз нагрузки на колл-центр

### Полная постановка

| поле                                 | решение                                                                                                                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Инициатива без слова `AI`            | Для каждого временного интервала и очереди заранее оценить ожидаемое число входящих обращений и диапазон неопределённости, затем рассчитать потребность в сотрудниках с учётом SLA и ограничений смен                                      |
| Какое действие изменится ?           | Планировщик смен получает прогноз и рекомендуемую численность, сравнивает сценарии и утверждает расписание; краткосрочные отклонения используются для оперативной корректировки                                                            |
| Где нужна обучаемая закономерность ? | В прогнозе потока обращений по истории, календарю, продуктовым событиям и известным кампаниям. Перевод нагрузки в численность, трудовые ограничения и формирование смен - расчёт/оптимизация, а не ML                                      |
| Чего не хватает ?, допущения         | Нужно уточнить горизонт, гранулярность, перечень очередей, целевой SLA, историю изменений телефонии и доступность календаря кампаний/сбоев. Предполагается стабильное логирование фактических входящих обращений и интервалов обслуживания |
| Вердикт                              | **ML-кандидат в звене прогноза; целевое решение является гибридным сервисом прогнозирования и оптимизации. Брать в пилот** после фиксации единицы прогноза и стоимости недо-/перепланирования                                              |

### Постановка модели и процесса

| поле                        | решение                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Бизнес-действие             | Скорректировать план смен, чтобы выдерживать SLA с меньшими переработками, простоем и потерянными обращениями                                                                                                                                                                                                                 |
| Объект и единица решения    | Число входящих обращений для одной очереди/канала за один временной интервал; отдельно может прогнозироваться среднее время обработки                                                                                                                                                                                         |
| Момент                      | Пакетно: базовый прогноз на недели вперёд для расписания и обновление за день/час для оперативного управления                                                                                                                                                                                                                 |
| Операция                    | Числовой вероятностный прогноз временного ряда: медиана и верхние квантили нагрузки                                                                                                                                                                                                                                           |
| Модальность                 | Временные ряды и таблицы: обращения, календарь, смены, кампании, релизы и известные события. Текст звонков для первого пилота не нужен                                                                                                                                                                                        |
| Выход модели                | Прогноз количества обращений по интервалу и очереди, интервалы/квантили неопределённости, флаг выхода за область известных режимов                                                                                                                                                                                            |
| Бизнес-выход                | Сценарий требуемой численности и смен, ожидаемый SLA и предупреждение о дефиците; окончательное расписание утверждает планировщик                                                                                                                                                                                             |
| Источник правильного ответа | Фактически поступившие обращения из платформы телефонии/омниканального контура после закрытия интервала; для оценки staffing-эффекта - SLA, abandon rate, переработки и оплаченные часы                                                                                                                                       |
| Конвейер                    | Контроль полноты событий -> агрегация временных рядов -> признаки известных будущих событий -> ML/статистический прогноз и интервалы -> детерминированный расчёт Erlang/оптимизация смен -> интерфейс планировщика -> факт и мониторинг ошибки                                                                                |
| Альтернативные постановки   | (1) Прогноз только числа звонков; (2) прогноз полной рабочей нагрузки с AHT; (3) сразу оптимальное расписание. **Вопрос бизнесу:** решение нужно для capacity planning или для готового расписания? Для пилота принят прогноз числа обращений и workload по очередям; оптимизатор остаётся отдельным детерминированным звеном |
